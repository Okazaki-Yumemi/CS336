# 8. 最大问题：怎么对 sampling 求梯度

# 10.为什么整个 response 的 log probability 能拆成 token？

数学公式推导我就不说了

>只知道最后答对，但整条 reasoning trajectory 都被 reinforcement。

这就是 sequence-level RL 的 credit assignment 很粗糙的地方。

# 11.为什么 REINFORCE 不够？——Variance

REINFORCE unbiased，但是variance很大, 假设rollout都答对,它们得到一样的scalar reward，但是具体的token trajectory可能完全不同，导致梯度估计方差很大。

# 12. Baseline：从 reward 变成 advantage

减去一个baseline, 只要 baseline 不依赖于当前 sampled action y , 梯度就不会有 bias。

而且减baseline之后，产生的负数值还能让模型知道这个 trajectory 不好。从而抑制

# 14.GRPO 的 Group Baseline

对一个prompt，采样 G 个response， 分别有reward r1, r2, ..., rG，然后计算平均作为这个prompt的baseline

# 17.GRPO 第二个改动：Advantage Standard-Deviation Normalization

还要除以 std

> 可以把它看成 stability trick，使不同 group 的 gradient update norm 更接近。

但是除以std后，不在保证estimator的expectation等于原始 $\nabla J$

# 20. GRPO 第三个改动：Sequence Normalization

每个response按照len取平均，这样每个sequence大致等权重
但 sequence normalization 也改变了原 objective

最终公式

$$ \hat g = \frac{1}{BG} \sum_{i=1}^{B} \sum_{j=1}^{G} \frac{1}{L_{ij}} A_{ij} \nabla_\theta \log \pi_\theta(y_{ij} | x_i,y_{<t}) $$

## 25. Off-policy

> rollout 是旧模型生成的，但当前模型已经更新了，这批旧 rollout 还能不能继续拿来训练？

On-policy 很多次数据只optimizer.step()一次，十分的昂贵

所以自然会想：

>生成一次 256 个 rollout，能不能拆成很多 minibatch，多训练几步？

但是更新一次之后，之前的 rollout 就不再是 on-policy 了。它是从老的 policy 生成的。
